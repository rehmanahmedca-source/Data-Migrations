## 5. Orphan recovery

**453 rows** referenced a client that does not exist in the legacy `client` table (no client code, and the name matches no client). They were **not** discarded. Instead **92 synthetic clients** named `Orphan1` … `Orphan92` were created (client `category = Orphan`, codes `ORPH-00001`…). Each orphan row now points at its orphan client, and the original client name is preserved in two places:

1. `client.page_notes` of the Orphan client — original name, original code and a per-table row count.
2. The `note` column of every recovered row — `[MIGRATION] Orphan record. Original client: "…"`.

So the data is fully visible in the new app and can be renamed/merged to the real client later.
