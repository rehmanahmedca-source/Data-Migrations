# Migration output

Everything here is generated by:

```bash
python3 tools/migrate.py    # build the migrated dataset in every format
python3 tools/verify.py     # cross-check all formats + write MIGRATION_REPORT.md
```

Source inputs are untouched: `test-files/legacy/Legacy Data28-08-2026_05-31PM.xlsx`
and `test-files/schemas/New App Data.xlsx`.

## What to use

| Goal | File |
|---|---|
| Restore the new app from a clean database | `sqlite/new_app_data.db` |
| Restore via SQL | `sql/new_app_data.sql` (schema + inserts) |
| Import through the app's XLSX importer | `xlsx/New App Data - MIGRATED.xlsx` |
| Start from an empty but complete schema | `xlsx/New App Data - EMPTY SCHEMA.xlsx` / `sql/new_app_schema.sql` |
| Feed another system | `json/new_app_data.json`, `json/new_app_data.ndjson`, `csv/*.csv` |
| See what happened | `MIGRATION_REPORT.md`, `orphan_client_map.csv`, `migration_stats.json` |

## Rules applied

1. All dummy data in the new-app file was deleted; every table and column was kept.
2. Voided rows (`is_void = true`) were never transferred — 44 rows.
3. Orphan rows (pointing at a client that does not exist) were kept and re-homed under
   synthetic clients `Orphan1` … `Orphan92`; the original client name lives in
   `client.page_notes` and in each row's `note`.
4. Everything else transferred 1:1 with its original ids, so all foreign keys still line up.

```bash
sqlite3 output/sqlite/new_app_data.db "SELECT COUNT(*) FROM client;"          # 407 (315 + 92 orphan)
sqlite3 output/sqlite/new_app_data.db "SELECT COUNT(*) FROM entry WHERE is_void;"  # 0
```
